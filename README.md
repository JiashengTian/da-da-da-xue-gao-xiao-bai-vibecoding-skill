# 🧊 大大大雪糕-小白 Vibecoding Skill

✨ 让零编程基础的用户，也能在 AI 的陪伴下把一个模糊想法做成真正能用的网站、App 或小工具。

这个 Skill 不追求“马上生成一堆代码”。它要求 AI 先持续提问、查找可靠的现成资源、给出清楚的提案和界面示意，再把程序拆成一个个小功能完成。每完成一块都要自己检查，并让用户决定下一步。

## 🎯 它解决什么问题

很多人有好点子，但不清楚如何把它说成开发需求；也很难判断 AI 做出来的页面是否真的好用。这个 Skill 把 AI 变成一位耐心的产品搭档：

- 把用户当作零基础新手，用日常语言沟通。
- 发现描述不清楚时继续追问，不擅自猜测。
- 每个问题都尽量给出可理解的选项，也允许用户用自己的话描述。
- 开发前先查 GitHub、官方文档、类似产品和可复用资源。
- 先展示功能、页面、风格和风险，再开始正式制作。
- 先做多个界面示意或可点击原型，得到确认后才进入成品开发。
- 一次只完成一个能验证的功能，不让新功能破坏已确认的旧功能。
- 如实报告检查结果、限制和风险，不为了迎合用户而掩盖问题。

## 🧭 完整工作流程

```text
💡 想法
  -> 🔍 发现：谁要用？要解决什么？
  -> 🧩 澄清：关键操作、数据、权限、异常和限制是什么？
  -> 🌐 调研：有哪些成熟方案、开源库和可靠资料？
  -> 🗺️ 提案：第一版做什么、页面怎么走、外观如何、有什么代价？
  -> 🎨 原型：先看 2-4 个关键界面并收集反馈
  -> 🛠️ 分块实现：一次完成一个功能并回归检查
  -> ✅ 验收交付：真实设备测试、使用说明、已知限制
```

没有需求确认、方案确认和原型确认，Skill 不会贸然开始正式开发。

## 💬 第一次会问什么

AI 会先用少量问题了解方向，例如：

1. 这个程序主要帮谁解决什么事？
2. 用户第一天最重要的一个操作是什么？
3. 主要在手机、电脑，还是两者上使用？
4. 希望更像清爽工具、好看的展示页、社区，还是其他风格？
5. 第一版最不能缺少的 1-3 件事是什么？

用户回答后，AI 会先复述自己的理解并等用户纠正。用户说“不确定”时，AI 要提供具体例子或保守默认方案，而不是抛出技术名词。

## 🧱 开发时如何保护成品质量

每个功能都是一个独立的小回合：

1. 说明这次要让用户获得什么能力，以及暂时不做什么。
2. 写出用户能理解的验收句，例如“我在手机上提交预约后，刷新仍能看到它”。
3. 完成最小可用路线。
4. 检查正常、失败、没有内容、网络慢、手机和电脑上的情况。
5. 回归检查已经完成的功能，发现退步先修复。
6. 用通俗语言报告进度，并让用户选择继续、调整或暂停。

## 🧰 资源调研能力

Skill 自带一份按用途分类的资源目录：

- 页面和交互灵感：Mobbin、Page Flows、Awwwards、Dribbble、Behance
- 界面构建：shadcn/ui、Radix、MUI、Tailwind CSS、Storybook
- 图标、字体、图片和插画：Lucide、Heroicons、Iconify、Google Fonts、Unsplash、Pexels、unDraw
- 动效和特殊交互：Motion、Lottie、React Flow、CSS-Tricks
- 表单、表格、图表和搜索：React Hook Form、Zod、TanStack Table、Recharts、ECharts、Algolia
- 登录、保存、付款、地图和通知：Supabase、Firebase、Stripe、MapLibre 等官方资料
- 质量保障：Playwright、axe-core、Lighthouse、W3C WAI、OWASP ASVS、OpenSSF Scorecard

资源目录只是起点。每次实际使用前，Skill 都要求检查官方文档、许可证、维护状态、费用、数据隐私、兼容性和替换成本。不能因为 GitHub 星标高、页面好看或示例能运行就直接复制到产品里。

## 🚀 使用方式

把本仓库链接直接发给 Codex、Claude Code 或其他支持 Agent Skills 的 AI 智能体，并说“请一键安装这个 Skill”。智能体会从仓库中识别 `SKILL.md` 并安装所需内容。

```text
请一键安装这个 Skill：
https://github.com/JiashengTian/da-da-da-xue-gao-xiao-bai-vibecoding-skill
```

安装完成后，直接这样开始：

```text
使用 $da-da-da-xue-gao-xiao-bai-vibecoding-skill，
我想做一个帮助我记录每日学习的手机网页，但我不知道要有哪些功能。
```

## 📁 文件说明

- `SKILL.md`：完整工作规则，包括提问、调研、原型、分步开发、检查和交付。
- `references/resource-catalog.md`：按用途分类的资源目录和选择原则。
- `agents/openai.yaml`：Codex 界面展示信息。

## 🛡️ 设计原则

- 不把专业术语和大量问题一次性丢给新手。
- 不在用户确认前偷偷扩大功能范围。
- 不复制竞品的品牌、内容、素材或未经核验的代码。
- 不让“好看”牺牲可读性、手机体验、性能、无障碍或安全。
- 不掩盖没有验证的地方、已知限制和现实成本。
